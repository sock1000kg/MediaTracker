Where MediaTracker's data comes from

MediaTracker gets its catalogue data from outside services. This page describes for each media type: which provider powers search, whose data is stored when you log something, what each import does, and how we follow each provider's rate limits and data rules. Summaries are as of 2026-11-18 and are not legal advice; the linked terms are what counts. Check them before adding features that use provider data in new ways.

Ground rules for every provider

Non-commercial only. No ads, paid tiers, selling data or selling access. Almost every free licence below depends on this.
No AI or machine learning on provider data. Never train, fine-tune or embed provider text (descriptions, reviews, keywords) and never feed it to a chatbot. Recommendation features may use the user's own notes, tags and ratings, and open data (Wikidata, Wikipedia, Open Library, MusicBrainz).
No redistribution. No exports of provider catalogues, no public API or feed that serves their data, no dataset downloads. A user's export of their own journal is fine.
On-demand only. Search when a person searches; fetch details when they log. Background jobs only fill in data for items users have already logged, never background catalogue sync.
Bring your own key for everything that needs one. One key or token identifies the app, not the person searching. Each user provides their own key for keyed providers (TMDB, RAWG, BGG, Last.fm); there is no shared server key or fallback. Keys are stored encrypted and never shown again.

Books

Open Library · no key
Terms
openlibrary.org/developers/api
Search
Open Library search.json, 20 results per page.
Stored on log
The search result as it came: title, authors, first publish year, cover URL, up to 3 subjects as categories, median page count, first publisher, ISBN. "View on Open Library" links are built dynamically from the work key (/works/<key>).
Import
Goodreads CSV. Stored with title, author, ISBN and Goodreads link. Background job syncs covers and categories via batched ISBN queries (up to 50 books per request) and fallback title/author queries.
Rules & Don'ts
Identify requests with a User-Agent containing contact info. Do not make hundreds of unbatched requests; never use as a bulk data backend.
Attribution
Credit Open Library on Book search.

Music

Last.fm (user key) + MusicBrainz + Cover Art Archive
Terms
Last.fm Terms · MusicBrainz API · Cover Art Archive
Search
Last.fm album and track search with per-user API key for ranking. Covers on the results page are fetched by sending release IDs to MusicBrainz in batches (up to 25 per request) and turned into Cover Art Archive links.
Stored on log
MusicBrainz is the primary stored source: release-group title, artist credit, first release year, primary and secondary types, up to 5 genres by vote, and a Cover Art Archive URL. Tracks store recording title, artist, length, and parent release group. Last.fm data is never stored, keeping its 100 MB storage cap out of play. Last.fm and MusicBrainz links are built dynamically from ids.
Rules & Don'ts
MusicBrainz strict 1 req/s rate limit. Last.fm images are excluded from its licence and never used. Covers come from the Cover Art Archive. Core MusicBrainz data is CC0; curated genres are CC BY-NC-SA.
Attribution
Credit Last.fm and link back to its pages. Credit Cover Art Archive on Music search. Credit MusicBrainz for tracklists and curated genres.
Termination
On termination, delete Last.fm data.

Anime & Manga

AniList · no key
Terms
AniList API Terms of Use
Search
AniList GraphQL, one request per page.
Stored on log
The search result as mapped: title, format, episode, chapter and volume counts, minutes per episode, score, MAL id, cover, genres. Links to AniList are built dynamically from id (/anime/<id> or /manga/<id>).
Import
MyAnimeList XML. MAL ids are resolved on AniList in batches of 50 per GraphQL request via the shared provider lookup.
Rules & Don'ts
Free for non-commercial use. 90 req/min limit (paced to ~85/min). Honors Retry-After and X-RateLimit-Remaining. Do not hoard data or use AniList in the app name.
Attribution
Credit AniList on Anime & Manga search.

Movies & TV

TMDB · user key
Terms
TMDB Terms of Use
Search
TMDB movie search or show search with seasons as child items.
Stored on log
The search result plus details (runtime, original language, IMDb id) stamped with fetchedAt. "View on TMDB" links are built dynamically from stored ids (/movie/<id>, /tv/<id>, /tv/<id>/season/<n>).
Import
Letterboxd ZIP. Each unique film is resolved via the shared TMDB findMovie lookup with your TMDB key.
Rules & Don'ts
6-month caching rule: TMDB data must not be cached for more than 180 days. A daily refresh job re-fetches stale items using a key holder's key, or purges description and image on 404 or missing keys. No AI/ML training on TMDB content.
Attribution
TMDB logo and notice: "This product uses the TMDB API but is not endorsed or certified by TMDB." Shown on Movie and TV search, Settings, and README.
Termination
On termination, promptly delete all TMDB content.

Video games

RAWG · user key
Terms
RAWG API Terms
Search
RAWG games search.
Stored on log
The search result plus details (description, developers, publishers, categories). Links to RAWG are built dynamically from stored slug or id (/games/<slug|id>).
Rules & Don'ts
Free for personal/hobby projects (20,000 req/month quota per user key). Do not redistribute or resell data.
Attribution
Active hyperlink to RAWG on every page displaying RAWG data.

Board games

BoardGameGeek · app token
Terms
BGG XML API Terms of Use
Search
BGG XML API2 search, then thing in batches of up to 20 ids at boardgamegeek.com (no www).
Stored on log
Stored exactly as received without modification (descriptions, ratings, players, play time, designers, categories) and formatted only for display. Links are built dynamically from id (/boardgame/<id>).
Rules & Don'ts
Registered non-commercial application token required. Space requests out; batch thing lookups. Do not modify data or use for AI/LLM training.
Attribution
Credit BoardGameGeek by name and show the unmodified "Powered by BGG" logo.

Other services and planned sources

Google Books (not active): Service code kept, UI disabled. If re-enabled, must follow Google's API terms and "Powered by Google" branding.
User-uploaded files (Not APIs): Goodreads, MyAnimeList and Letterboxd imports read export files uploaded by the user. We do not call those services' private APIs.
Planned open data: Wikidata (CC0 structured links and IDs) and Wikipedia (CC BY-SA 4.0 plot/premise text for opt-in local embeddings). Commercial provider text is never embedded.

Central provider registry and rate limits

All provider HTTP requests go through a unified providerFetch function and registry in server/src/providers/. Every call enforces the provider's rate limiter, User-Agent, user auth, timeout, automatic single retry on 429/503 with Retry-After, and typed error mapping.
